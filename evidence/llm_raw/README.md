# evidence/llm_raw/

**These files are verbatim recordings of live Gemini 3.6 Flash output.** They
are NOT hand-crafted, NOT edited, NOT simplified. Each `<key>.json` here is
exactly what the model returned when the classifier was run in `--mode record`
against the batch generated by `python -m src.generator --seed 42`.

The classifier speaks to Gemini through the `LLMBackend` Protocol defined in
[src/classifier/backend.py](../../src/classifier/backend.py); the concrete
backend used to produce the files here is `GeminiBackend` (model:
`gemini-3.6-flash` — `gemini-2.5-flash` was retired for new users while this
build was in progress).

## What these recordings actually show

On this batch the model got 11 / 12 escalations right and produced **0 false
reconciliations** — including both adversarial near-misses (ORD-0006, ORD-0011)
and the orphan payout. See [../README.md](../README.md) for the full framing:
the guard is defense-in-depth because 11/12 is not a scale-safe number, not
because we caught this run misbehaving. The hand-crafted adversarial fixtures
that exercise the guard live in [../../tests/fixtures/](../../tests/fixtures/)
— they are the "would-be false reconciliations" the guard is proven to reject.

```json
  "response_text": "<verbatim model output>"

```

## Why record + replay

- **Reproducibility.** The demo, CI, and reviewers all replay the same responses
  the first live run captured. Nobody burns API calls to re-run the pipeline.
- **Provenance.** The pitch says "these are real hallucinations from a real
  model." That claim is only true if the responses are stored verbatim.
- **Cost.** Live LLM calls have a monetary and latency cost; making the demo
  replay-by-default keeps the pipeline runnable end-to-end offline.

## Strict separation from test fixtures

Hand-crafted LLM-shaped responses used by the step-4 validation-guard tests
live in `tests/fixtures/`. **The two directories do not share files, ever.**
If you find yourself wanting to hand-edit a file in `evidence/llm_raw/`,
you are about to invalidate the "verbatim recording" claim — write a test
fixture instead.

## How to (re)record

```bash
# One-time setup:
#   cp .env.example .env
#   put GEMINI_API_KEY in .env  (free tier: https://aistudio.google.com/apikey)
python -m src.classifier --mode record
```

Regenerate whenever the batch (generator seed / scenario mix) or the prompt
changes. Otherwise, leave them alone.
